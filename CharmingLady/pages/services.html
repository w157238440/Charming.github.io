服务与合作 · 北京 · 可远程

把一件事做完，比把十件事开头更有价值。

我接的项目大多有一个共同点：需求方知道自己「缺一个东西」，但说不清具体缺什么。 我的第一件事不是报价，而是把这个「缺」拆成可以验收的条目——拆不清楚的项目，我不会接。

响应时间 · 工作日 24 小时内 / 档期 · 通常提前 2–3 周 / 合作方式 · 远程为主，北京可面谈

能做的四类事

每一类都按「你能拿到什么」来写，而不是按我的技术栈来写。技术栈在 关于页里有完整清单。

01 / 前台与官网

能被人搜到、愿意看完的页面

企业官网、产品落地页、活动页、个人站。重点不是「好看」，而是三件具体的事： 首屏能在 2 秒内出内容、手机上不用横向滚动、改文案不用找开发。

  • 信息结构梳理与文案落位
  • 响应式与深浅主题
  • 静态化部署（GitHub Pages / OSS / 服务器）
  • SEO 基础项：标题、描述、结构化数据、站点地图

参考周期 · 1–3 周

02 / 后端与接口

让数据按规矩流动的那一层

账号体系、权限、订单、支付回调、消息通知。后端最容易出事的地方不是写不出来， 而是「重复提交」「回调重放」「时区算错」，这些我在项目里都踩过，也都有固定检查项。

  • Node / NestJS、Python 接口服务
  • MySQL / PostgreSQL 表设计与索引
  • 登录鉴权、限流、日志与错误追踪
  • 支付与第三方回调（含幂等处理）

参考周期 · 2–6 周

03 / 小程序

在微信里跑通的那条最短路径

门店预约、活动报名、内部工具、会员卡包。小程序的门槛从来不在页面， 而在授权顺序、审核规则和「用户换了手机之后数据还在不在」。

  • 原生小程序 / uni-app 双端
  • 登录授权与手机号获取
  • 订阅消息、模板消息、客服消息
  • 提审材料与常见驳回项排查

参考周期 · 2–4 周

04 / 数据与工具

把重复劳动变成一次点击

内部看板、数据导出、批量处理脚本、给同事用的填报表单。 这类需求通常预算不高，但省下来的时间最实在——所以我愿意接，也愿意先做最小可用版本。

  • 数据看板与图表（按口径算，不目测）
  • Excel / CSV 批处理与校验脚本
  • 内部表单与审批流轻量实现
  • 老项目排错、性能与可读性整理

参考周期 · 3 天–2 周

三档合作方式

价格给的是区间，不是报价单。区间取决于三件事：页面数量、是否需要后端、是否要接第三方。 真实的数字在需求澄清之后给你，写进报价单，写清包含与不包含。

单点交付

最小范围 · 最常用

参考区间 ¥3,000–8,000 / 单项目

一个页面组、一个接口、一个小程序页面、一次排错。适合「只想把眼前这一件解决掉」的情况。

  • 需求澄清 1 次（线上，30–45 分钟）
  • 方案与工作量确认（书面）
  • 开发 + 自测 + 部署
  • 交付源码与一份说明
  • 上线后 7 天内免费修 bug

不含 · 内容撰写 / 平面设计 / 长期维护

整站 / 整端交付

从零到上线

参考区间 ¥12,000–35,000 / 单项目

官网 + 后台、小程序 + 接口、看板 + 数据管道。适合需要「有人对整个链路负责」的情况。

  • 信息结构与页面规划
  • 前端 + 后端 + 部署一条线
  • 基础文档：结构说明、部署手册、接口说明
  • 两次修改轮次（每次范围不超过原范围的 20%）
  • 上线后 30 天内免费修 bug
  • 一次线上交接会议（录屏 + 文字纪要）

不含 · 服务器与域名费用 / 第三方服务年费 / 内容拍摄

长期协作

按月度投入

参考区间 ¥6,000–15,000 / 月

每月固定投入时间，处理迭代、维护、排错、临时需求。适合已经有产品、需要稳定人手的情况。

  • 每月固定可投入天数（按 8 小时/天计）
  • 需求排队与优先级由双方每周对齐一次
  • 线上问题响应：工作日 4 小时内首次回复
  • 每月一份改动清单与遗留问题清单
  • 可提前一个月书面终止

不含 · 超出约定天数的部分按日单价另计

付款方式：单点与整端按 3 / 4 / 3 三段（启动、里程碑、验收），长期协作按月预付。 发票可开，税率与抬头在报价单里写明。

交付物清单

「做完了」的标准是可以被第三个人接手，所以交付物固定为四项。

源码

完整可运行的代码仓库，含依赖说明与启动命令。分支与提交记录保留，不做「压缩成一个包」式的交付。

文档

结构说明、部署手册、接口约定三份。写的是「为什么这么放」，而不只是「文件在哪里」。

部署

域名、证书、构建、发布流程都配好并演练一遍。上线当天我在线，不把风险留给你。

交接

一次录屏会议 + 一份文字纪要，讲清「哪里最容易改坏」。后续谁接手都能看懂。

验收清单

按功能、性能、兼容、安全四组列条目，逐条打勾。没过的条目写进遗留问题，不藏在口头承诺里。

上线后观察

前 3 天看错误日志与访问数据，有问题主动说，不等你发现。之后按约定进入维护期。

合作流程

四步，每一步都有明确的产出物；任何一步没有结论，就不进入下一步。

第 1 步

需求澄清

30–45 分钟线上沟通，我问的通常不是「你想要什么风格」，而是「谁来用、多久用一次、出错会怎样」。 结束后我给你一份一页纸的理解确认，你确认无误才算对齐。

产出 · 需求理解确认（1 页）

第 2 步

方案与拆解

把需求拆成可验收的条目，标出前置依赖与风险点（第三方审核、素材缺失、接口权限）。 同时给报价单与工期表，写清包含什么、不包含什么。

产出 · 方案说明 + 报价单 + 工期表

第 3 步

开发与阶段可见

每 3–5 天给一次可访问的进度地址，而不是等到最后一天交付。你随时能看到真实页面， 不用靠想象判断进度。过程中发现的变更，走书面变更单，避免口头叠加。

产出 · 可访问的预览环境 + 进度记录

第 4 步

验收、上线与交接

按验收清单逐条确认，全部通过后部署上线，再做一次交接会议。 上线后 3 天我主动看日志；维护期内的 bug 修复不额外收费。

产出 · 验收清单（已签字）+ 交接纪要
