装备与工具 · 北京

工具决定不了水平，但决定了你一天能改几次。

下面是目前真实在用的东西。判断标准只有两条：出问题时我能不能自己查清、 以及换掉它要花多少天。凡是「换掉成本高于收益」的，就一直留着。

最后更新 · 2026-11 / 机器 · Windows 11 / 口径 · 个人开发环境，非生产集群

机器

一台拉满的主力台式机：编译、三个容器、安卓模拟器、本地模型推理同时开，风扇仍然是安静的。这套配置按「五年不换主板」挑的。

CPU · Intel 酷睿 i9-14900K

24 核 32 线程，睿频 6.0GHz。全量编译从 3 分半压到 50 秒，是这台机器里提升最直观的一项；P 核跑编译、E 核留给容器与后台任务。

在用

主板 · 华硕 ROG MAXIMUS Z790 DARK HERO

18+1+2 相供电、双 PCIe 5.0 插槽、板载 Wi-Fi 7 与 10G 网口。选它不是为了超频，是为了五年内不用再为接口不够换板。

在用

内存 · 芝奇 Trident Z5 RGB DDR5 6400 64GB（32G×2）

开 Hyper-V 跑三个容器、两个 IDE、二十个浏览器标签，占用长期在 28GB 上下。上 64GB 之后，第一次不用为了省内存去关东西。

在用

显卡 · 微星 GeForce RTX 4090 SUPRIM X 24G

24GB 显存是真正的分界线：本地 30B 级模型能整块放进去，批量图像处理也不再排队。游戏是顺带的，卡买来是干活的。

在用

系统盘 · 三星 990 PRO 2TB PCIe 4.0 NVMe

顺序读 7450MB/s。系统、工具链、常用仓库放这里，索引与依赖缓存不再拖慢搜索；分区只分两个：系统、数据。

在用

数据盘 · 希捷 酷狼 Pro 8TB（2×4TB · 镜像）

素材、镜像、旧项目归档，两块盘做镜像，坏了有征兆也有备份。机械盘负责「大而冷」的数据，热数据一律留在 NVMe 上。

在用

电源 · 海韵 PRIME TX-1000 钛金 1000W 全模组

4090 的瞬时功耗峰值很凶，钛金 1000W 的余量给的是稳定性而不是数字。全模组只为走线，单路 12V 的余量才是关键。

在用

散热 · 恩杰 Kraken 360 一体水冷

14900K 满载会顶到温度墙，360 冷排能把长时编译压在 80℃ 以内。风扇曲线按噪音调，宁可高 3℃ 也不愿意听高频啸叫。

在用

显示器 · 27 英寸 4K 主屏 + 27 英寸 2K 竖屏

主屏 4K 开 150% 缩放，代码不放大也清楚；竖屏专放日志、文档和调试面板。整套设备里，对效率影响最大的其实是这块竖屏。

在用

键盘鼠标 · 87 键热插拔机械键盘 + 轻量无线鼠标

不要小键盘，右手要给鼠标留位置；鼠标只用一个侧键，映射成浏览器后退。键盘换轴不换壳，敲击手感比参数表重要。

在用

软件

原则：能读源码的优先，能在终端里干完的不装 GUI，配置文件全部进版本库。

编辑器 · VS Code

插件只留 6 个（语言支持、格式化、Git 图形、REST 调试、数据库、主题）。插件越多越容易在排查问题时被怀疑。

在用

终端 · Windows Terminal + PowerShell 7

PowerShell 负责系统层，Git Bash 负责 Unix 习惯。两边都用同一份 alias 配置，避免在错误的环境里敲命令。

在用

版本控制 · Git + 自建裸仓库

公开项目在 GitHub，私有项目在一台小机器上的裸仓库。分支只留三种：main、feat、fix。

在用

容器 · Docker Desktop

本地跑 MySQL、Redis、Nginx 三个容器。用它是因为「和生产一致」这件事能省掉大量「我这里是对的」的争论。

在用

接口调试 · REST Client（VS Code 插件）

请求写在文件里，跟代码一起进仓库，谁接手都能直接跑。比把请求存在某个 GUI 工具里可靠。

在用

数据库客户端 · DBeaver

只为看表结构和跑一次性查询。日常数据操作一律写成脚本，避免「手点出来的结果没法复现」。

在用

截图与标注 · 系统截图工具 + 手写批注

给需求方反馈问题时，一张标注过尺寸与位置的图，比一段描述省三轮沟通。

在用

笔记 · 纯 Markdown + 本地目录

不用带数据库的笔记软件：十年后还能打开的东西，才值得存十年。目录按项目分，文件名带日期。

在用

密码管理 · 本地加密库

不用浏览器记住任何生产密码。密钥与证书单独存放，绝不进代码仓库。

在用

技术栈

按「能独立交付」的标准筛过一遍：只列自己能从零搭到上线的东西。

前端

Vue 3（含 Pinia / Vue Router）、React、TypeScript、Vite、Tailwind 与原生 CSS 双轨。

无框架场景直接用 HTML + CSS + 原生 JS，就像这个站点——不是所有项目都需要构建链。

关注点 · 首屏、可访问性、主题与响应式

后端

Node.js / NestJS、Python（FastAPI）、MySQL、PostgreSQL、Redis、Nginx、Docker Compose。

写过支付回调、消息队列、定时任务、权限模型；也被幂等和时区坑过，所以这些是固定检查项。

关注点 · 幂等、可观测、备份与回滚

小程序

微信原生小程序、uni-app（微信 / H5 双端）、云开发与自建后端两种接法。

熟悉授权链路、订阅消息、审核规则、包体积压缩与分包加载。

关注点 · 审核通过率、授权顺序、弱网体验

部署与运维

GitHub Pages、静态对象存储、Linux 服务器（systemd + Nginx）、GitHub Actions 自动化。

会看日志、会抓包、会读火焰图，能定位「慢」是慢在数据库还是慢在网络。

设计与文档

能独立做信息结构与界面排版，不依赖设计稿也能交付可用的界面。

文档习惯：结构说明、部署手册、接口约定三件套，交付即写。

刻意不用的东西

不接「一键生成后台」的模板项目，不写无法解释的脚手架，不用说不清依赖来源的第三方包。

不是洁癖，是因为出问题时没人能替你查。

你的项目，未必需要这么全。

大多数需求只需要其中一两样。与其照着清单堆技术，不如先想清「谁来维护、多久改一次」， 再决定要多少东西。这件事我可以帮你判断。
