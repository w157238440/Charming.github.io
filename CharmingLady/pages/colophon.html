站点说明 · 2026

把做法也写出来，比只写结果更有用。

这一页交代四件事：这个站被什么约束着、文件怎么分层、动效为什么这么安排、 以及你怎样在本地把它跑起来并验证一遍。全部是手写的，没有构建步骤，也没有隐藏脚本。

形态 · 纯静态 / 依赖 · 零外部 / 许可 · 代码 MIT · 内容 CC BY-NC 4.0

01 · 硬约束

六条不让步的规则。

这些规则决定了站点的上限：它不会比这更快、更花哨，但也不会突然崩掉。

零依赖

不用框架、不用构建工具、不用 CDN、不加载 webfont。字体只用系统栈（等宽体负责技术气质）。

代价 · 没有组件复用，靠分层 CSS 与注释维持秩序

断网可开

把整个目录拷到 U 盘，双击 index.html 就能完整浏览：图片本地化、无外部请求、无接口调用。

代价 · 所有内容必须内联，详情用 <template> 而不是 fetch

首屏不依赖 JS

正文、标题、数据带都是写死在 HTML 里的。JS 只负责「让它更好看」，不负责「让它出现」。

代价 · 每个页面首行都要带一句 class 标记，见下面的校验清单

一份内容一处来源

项目、笔记、FAQ 的正文只写一次；列表项与详情模板一一对应，改文案不会忘掉另一处。

代价 · 页头页脚在每个页面各有一份副本，靠脚本统一注入

动效可关闭

所有位移、缩放、描绘、逐字入场都遵守 prefers-reduced-motion：关掉后信息量不变，只是不动。

代价 · 每个动效模块都要写一条静态分支，工作量翻倍

只改合成属性

动效只碰 transform 与 opacity，不碰 width / height / top / left，避免每一帧都重排。

代价 · 某些「自然」的过渡要绕路实现，例如用 scaleX 而不是改宽度

02 · 结构

根目录只放九件事。

页面集中放在 pages/，样式与脚本按类型分层，文档单独一个目录。加页面只动三处。

tree · 站点根目录

03 · 分层

五层 CSS，八个 JS。

分层的目的不是好看，是让「改一处」不会牵动另一处。

CSS · 由抽象到具体

base 令牌、重置、排版、工具类；layout 页头/抽屉/区块骨架/页脚；components 按钮、卡片、时间轴、代码窗口；effects 22 节动效与初始态；pages 各页独有版式。

加载顺序即优先级，后面的层只覆盖，不反向依赖

JS · 由通用到具体

core 主题、抽屉、吸顶、进度、回顶；effects 12 个动效模块，统一注册；ui 弹层、手风琴、筛选器；其余五个是页面级的列表、模板映射与留言簿数据层。

全部普通脚本 + defer，没有模块打包，也没有全局命名冲突

主题 · 一处切换

颜色全部走 CSS 变量；深色是同一套变量的反色板，不是第二套样式。切换只改 data-theme 与 meta theme-color。

首选项存在 localStorage（键 cl-theme），没有则跟随系统

04 · 动效

十二种，各出现一次。

原则：首屏一次编排，其余每个模块只一种特效、只播一次、只改合成属性。

  1. 首屏分层入场 · data-enter 1–6：眉标、标题、正文、按钮、代码窗口、图片依次进入，总时长控制在 900ms 内，只播一次。
  2. 首屏极光 · 两层径向渐变以极慢速度漂移，叠加噪点；为不抢标题，透明度压得很低。
  3. 打字机 · 首页副标题逐字出现，光标用伪元素闪烁；跳过按钮与 reduced-motion 分支都会直接给全文。
  4. 数字滚动 · 进入视口后从 0 缓动到目标值，只跑一次；数值本身写死在 HTML 里，JS 缺席时仍是正确数字。
  5. 标题逐字入场 · data-split：整段拆成单字 span 后按 26ms 递进显现，原文进 aria-label，拆出的字全部 aria-hidden。
  6. SVG 描边 · data-draw：路径用 stroke-dashoffset 从全隐到全显，像被一笔画出来。
  7. 卡片扫描线 · 悬停时一条细线自左掠过卡片上缘，代表「被读过一次」；只用 scaleX。
  8. 磁吸按钮 · 指针靠近时按钮朝指针方向偏移最多 4px，离开归零；仅精确指针设备启用。
  9. 卡片倾斜 · 指针在卡片上移动时按位置算出 ±2° 的 3D 倾斜，离开回正。
  10. 视差图片 · 滚动时图片内部轻微反向位移，制造层次；位移量按滚动进度线性映射。
  11. 能力条 · 关于页的技能条按百分比从 0 长到目标值，数字同步计数。
  12. 回顶环形进度 · 右下角按钮外圈随滚动进度画弧，滚到底时闭合成整圆。

05 · 性能

不追分数，追「打开就能读」。

下面是与体验直接相关的几条取舍，按影响从大到小排。

首屏内容写死在 HTML 里

标题、正文、统计数字都不等 JS。禁用脚本、脚本 404、旧浏览器，看到的都是完整内容，只是没有动效。

实测 · 关掉 JS 后 11 个内容页内容完整、无空白（留言簿的留言列表除外：那是数据，只能在 JS 里算出来）

图片本地化并限定尺寸

8 张图全部落在本地，最宽的 hero 为 1440×810；列表封面统一 1200×900，用固定比例容器裁切，避免加载时抖动。

实测 · 首屏不再依赖任何外部域名

动效只在需要时启动

首屏以外的模块由 IntersectionObserver 触发，播完即解绑；页面不可见（切走标签页）时暂停 Canvas 绘制。

实测 · 静止时无持续 rAF 循环

06 · 运行与校验

两步跑起来，一条命令查一遍。

不需要 Node、不需要装包。有 Python 就够了；没有也可以用任何静态服务器。

terminal · 本地预览与校验
# 1) 起一个本地服务（不要直接双击 html，相对路径在 file:// 下虽然能开， # 但某些浏览器会限制部分特性） python -m http.server 8090 # 2) 打开首页与内容页 # http://127.0.0.1:8090/ # http://127.0.0.1:8090/pages/about.html # 3) 校验（脚本在项目外的 _tmp/ 里，随项目一起交付） # 检查：页面清单、相对路径、图片是否都在、是否误引外部域名 python _tmp/validate.py # 4) 窄屏复核：把窗口拖到 375px，或打开「减少动态效果」看最终布局

校验清单（8 条）

页面清单齐全 · 每个链接可解析 · 图片存在 · 无外部域名 · 无未替换占位 · 每页有 data-page · 每页首行有 js 标记 · sitemap 与实际页面对应。

已知取舍（3 条）

页头页脚逐页复制（零框架的代价，靠脚本注入统一）；详情用内联模板（file:// 不能 fetch）；不用 webfont（换字体一致性的代价换加载速度）。

不适合的场景

需要登录、需要后台、需要实时数据、需要多人协作编辑的内容站，不适合用这套纯静态方案；这类需求应当上真正的应用框架与数据库。
